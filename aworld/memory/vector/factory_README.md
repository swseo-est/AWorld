# 벡터 데이터베이스 팩토리 모듈 (`factory.py`)

이 스크립트는 다양한 벡터 데이터베이스 구현체를 생성하는 책임을 맡는 `VectorDBFactory` 클래스를 정의합니다. 이는 팩토리 메서드(Factory Method) 디자인 패턴의 간단하고 효과적인 구현입니다.

## 주요 구성 요소

### `VectorDBFactory` (팩토리 클래스)

이 클래스는 단 하나의 정적 메서드(`get_vector_db`)를 통해 벡터 데이터베이스 인스턴스를 생성하는 중앙화된 지점을 제공합니다.

#### `get_vector_db` (정적 메서드)

-   **역할**: 설정 객체(`VectorDBConfig`)를 받아, 그에 맞는 올바른 `VectorDB` 구현체 인스턴스를 생성하여 반환합니다.
-   **입력**: `VectorDBConfig` 객체를 인자로 받습니다. 이 객체 안에는 `provider` (예: "chroma")와 해당 제공자를 위한 세부 설정(`config`)이 들어있습니다.
-   **로직**:
    1.  `if/elif` 문을 사용하여 `provider` 문자열을 확인합니다.
    2.  `provider` 이름에 따라, 해당하는 `VectorDB` 구현 클래스(예: `ChromaVectorDB`)를 동적으로 임포트(import)합니다.
    3.  해당 클래스를 세부 설정과 함께 인스턴스화하여 반환합니다.
    4.  지원되지 않는 `provider`가 명시되면 `ValueError`를 발생시킵니다.

#### 디자인 패턴의 이점

-   **디커플링(Decoupling)**: 팩토리를 사용함으로써, 벡터 데이터베이스를 *사용하는* 코드(예: `AworldMemory`)와 데이터베이스 인스턴스를 *생성하는* 코드를 분리할 수 있습니다.
-   **확장성**: 향후 새로운 벡터 데이터베이스(예: "milvus")를 지원해야 할 경우, 개발자는 새로운 구현 클래스를 작성하고 이 팩토리 파일에 `elif` 블록 하나만 추가하면 됩니다. 프레임워크의 다른 부분은 수정할 필요가 없습니다.

요약하자면, `VectorDBFactory`는 설정에 따라 적절한 데이터베이스 드라이버를 생성하고 반환하는 역할을 합니다. 이는 시스템의 유연성과 확장성을 크게 향상시키는 중요한 설계 요소입니다.
