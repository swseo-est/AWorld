# 다중 에이전트 시스템 모듈 (`swarm.py`)

이 스크립트는 AWorld 프레임워크에서 다중 에이전트 시스템(Multi-Agent System, MAS)을 구성하고 관리하는 핵심 구성 요소들을 정의합니다. `Swarm` 클래스를 통해 여러 에이전트를 다양한 협업 구조(토폴로지)로 연결할 수 있습니다.

## 주요 구성 요소

### `Swarm` 클래스

`Swarm`은 다중 에이전트 시스템을 나타내는 기본 클래스입니다. 여러 에이전트를 모아 하나의 그룹으로 만들고, 이들 간의 상호작용 방식을 정의합니다.

-   **토폴로지(`topology`)**: `Swarm`의 가장 중요한 인자는 `topology`입니다. 이는 에이전트 간의 연결 관계와 실행 흐름을 정의하는 리스트입니다.
-   **빌드 유형(`build_type`)**: 토폴로지가 해석되고 실행되는 방식을 결정합니다. `GraphBuildType` 열거형을 통해 지정됩니다.
-   **빌더(`builder`)**: `topology`와 `build_type`을 바탕으로 내부적으로 `AgentGraph`를 생성하는 역할을 합니다.

---

### `GraphBuildType` 열거형 (Enum)

에이전트 스웜이 구성되고 작동하는 세 가지 주요 패러다임을 정의합니다.

1.  **`WORKFLOW` (워크플로우)**
    -   에이전트들이 지정된 순서대로 실행되는 결정론적 프로세스입니다.
    -   주로 방향성 비순환 그래프(DAG) 구조를 가집니다.
    -   예: `Agent1 -> Agent2 -> Agent3`

2.  **`HANDOFF` (핸드오프/협업)**
    -   에이전트가 다른 에이전트에게 작업을 위임(handoff)할 수 있는 협업 모델입니다.
    -   에이전트들이 서로를 도구처럼 사용하며, 복잡한 상호작용과 순환 구조(DCG)를 형성할 수 있습니다.
    -   예: `Agent1`이 `Agent2`를 호출하고, `Agent2`의 결과에 따라 다시 `Agent1`이나 `Agent3`을 호출할 수 있습니다.

3.  **`TEAM` (팀/조정)**
    -   하나의 리더(마스터) 에이전트가 다른 워커 에이전트들에게 작업을 분배하고 조정하는 모델입니다.
    -   일반적으로 별(Star) 모양의 토폴로지를 가집니다.
    -   예: 리더 에이전트가 여러 전문가 에이전트에게 하위 작업을 맡기고 결과를 취합합니다.

---

### `TopologyBuilder`와 하위 클래스

`TopologyBuilder`는 사용자가 정의한 `topology`를 내부적인 `AgentGraph`로 변환하는 역할을 하는 추상 클래스입니다. `GraphBuildType`에 따라 다음과 같은 구체적인 빌더 클래스가 사용됩니다 (전략 디자인 패턴).

-   `WorkflowBuilder`
-   `HandoffBuilder`
-   `TeamBuilder`

이 빌더들은 `Swarm` 클래스에 의해 내부적으로 호출되어, 복잡한 토폴로지 구성 로직을 추상화합니다.

---

### `AgentGraph` 클래스

`AgentGraph`는 다중 에이전트 시스템을 방향성 그래프로 표현하는 내부 데이터 구조입니다.

-   **노드(Nodes)**: 각 에이전트는 그래프의 노드에 해당합니다.
-   **엣지(Edges)**: 에이전트 간의 연결(실행 순서, 위임 관계 등)은 엣지로 표현됩니다.
-   **그래프 연산**: 노드 및 엣지 추가/삭제, 진입/진출 차수 계산 등 그래프 관련 연산을 위한 메서드를 제공합니다.

---

### `WorkflowSwarm`, `TeamSwarm`, `HandoffSwarm`

`Swarm` 클래스를 상속하고 `build_type`을 미리 지정해 둔 편의 클래스들입니다. 사용자는 이 클래스들을 통해 스웜의 유형을 더 명시적으로 선언할 수 있습니다.

결론적으로, `swarm.py` 모듈은 개발자가 간단한 파이썬 리스트와 튜플을 사용하여 복잡한 다중 에이전트 협업 구조를 유연하고 강력하게 정의할 수 있도록 해주는 핵심적인 추상화 계층입니다.
