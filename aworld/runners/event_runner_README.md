# 이벤트 기반 실행기 모듈 (`event_runner.py`)

이 스크립트는 `TaskRunner`의 구체적인 구현체인 `TaskEventRunner`를 정의하며, AWorld 프레임워크의 이벤트 기반 실행 모델의 핵심입니다. 에이전트와 도구 간의 모든 상호작용은 메시지(이벤트)를 통해 비동기적으로 처리됩니다.

## 주요 구성 요소

### `TaskEventRunner` 클래스

`TaskRunner`를 상속받아 이벤트 기반 실행 로직을 구현합니다. 이 실행기는 태스크를 단계별로 진행시키기 위해 중앙 이벤트 버스를 사용합니다.

#### 주요 책임:

-   **이벤트 관리자 (`EventManager`)**: 실행기는 `EventManager` 인스턴스를 생성하여 모든 통신을 관리합니다. 에이전트와 도구는 서로를 직접 호출하는 대신, 이벤트 버스에 메시지를 발행(publish)하고, 관심 있는 토픽의 메시지를 구독(subscribe)하여 처리합니다.

-   **사전 실행 (`pre_run`)**:
    -   가장 중요한 설정 단계입니다. 부모 클래스의 `pre_run`을 호출하여 기본 설정을 마친 후, 이벤트 핸들러를 등록합니다.
    -   **핸들러 등록**: 스웜 내의 모든 에이전트와 태스크의 모든 도구를 순회하며, 각각의 `run` 또는 `step` 메서드를 해당 에이전트/도구의 고유 토픽에 대한 콜백 함수(핸들러)로 `EventManager`에 등록합니다.
    -   **프레임워크 핸들러 등록**: `handler/` 디렉토리에 정의된 핸들러들을 등록합니다. 이들은 로깅, 상태 관리, 태스크 종료 조건 확인 등 시스템 전반의 기능을 수행합니다.
    -   **첫 메시지 생성**: 태스크를 시작하기 위한 첫 번째 `AgentMessage` 또는 `ToolMessage`를 생성하여 이벤트 큐에 넣습니다.

-   **핵심 실행 (`do_run`)**:
    -   메인 실행 루프입니다. `while True` 루프 안에서 `EventManager`로부터 메시지를 하나씩 소비(`consume`)합니다.
    -   `_common_process` 메서드를 통해 소비된 메시지에 적합한 핸들러(예: 특정 에이전트의 `run` 메서드)를 찾아 실행합니다.
    -   핸들러(에이전트 등)는 자신의 로직을 수행한 후, 다음 행동을 나타내는 새로운 메시지(예: 도구 호출을 위한 `ToolMessage`)를 반환합니다.
    -   이 새로운 메시지는 프레임워크 레벨의 로직(`_inner_handler_process`)을 거친 후, 다시 이벤트 버스로 발행(`emit`)됩니다.
    -   이 과정은 특정 핸들러가 태스크 종료를 결정하고 `self.stop()`을 호출할 때까지 계속 반복됩니다.

#### 이벤트 기반 아키텍처의 장점

-   **디커플링(Decoupling)**: 이 아키텍처는 에이전트와 도구 간의 의존성을 크게 낮춥니다. 각 컴포넌트는 다른 컴포넌트의 내부 구현을 알 필요 없이, 단지 어떤 종류의 메시지를 발행하고 구독할지만 알면 됩니다.
-   **확장성**: 새로운 에이전트, 도구, 또는 프레임워크 기능을 추가할 때, 기존 코드를 수정하는 대신 새로운 핸들러를 등록하기만 하면 되므로 시스템 확장이 매우 용이합니다.

결론적으로, `TaskEventRunner`는 복잡한 다중 에이전트 시스템의 비동기적 워크플로우를 관리하기에 매우 적합한 고전적인 이벤트 루프 아키텍처를 구현합니다.
