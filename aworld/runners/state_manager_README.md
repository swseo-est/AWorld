# 런타임 상태 관리자 모듈 (`state_manager.py`)

이 스크립트는 `TaskEventRunner`가 태스크를 실행하는 동안 발생하는 모든 이벤트와 상태를 추적하고 관리하는 핵심 컴포넌트를 정의합니다. 실행 과정을 하나의 그래프로 보고, 각 노드의 상태를 기록하여 전체 워크플로우를 관찰하고 제어할 수 있게 합니다.

## 주요 구성 요소

### `RunNode` (Pydantic 모델)

`RunNode`는 실행 그래프의 단일 노드(하나의 처리 단계)를 나타내는 데이터 모델입니다.

-   **핵심 아이디어**: 에이전트의 실행, 도구 호출 등 메시지 핸들러가 처리하는 각 단계를 하나의 `RunNode`로 표현하여 그 상태를 추적합니다.
-   **주요 필드**:
    -   `node_id`: 노드의 고유 ID (일반적으로 이 노드를 트리거한 메시지의 ID와 동일).
    -   `busi_type`: 노드의 비즈니스 유형 (예: `AGENT`, `TOOL`, `TASK`).
    -   `status`: 노드의 현재 상태 (`INIT`, `RUNNING`, `SUCCESS`, `FAILED` 등).
    -   `results`: 해당 노드의 핸들러가 반환한 결과(`HandleResult`) 목록.
    -   `parent_node_id`, `group_id`: 다른 노드와의 부모-자식 관계 및 그룹 정보를 저장하여 복잡한 워크플로우를 표현합니다.

---

### `StateStorage` (추상 기본 클래스)

`RunNode`들의 상태를 저장하기 위한 저장소의 인터페이스를 정의합니다.

-   **`InMemoryStateStorage`**: 기본 구현체로, 모든 노드 정보를 파이썬 딕셔너리에 인메모리(in-memory) 상태로 저장합니다. 간단하고 빠르지만 영속성이 없습니다. 실제 운영 환경에서는 데이터베이스 기반의 구현체로 교체될 수 있습니다.

---

### `RuntimeStateManager`

상태를 관리하기 위한 API를 제공하는 메인 클래스입니다.

-   `StateStorage` 구현체를 사용하여 노드 상태를 영속화합니다.
-   `create_node`, `run_node`, `run_succeed`, `run_failed`와 같은 메서드를 제공합니다. 이 메서드들은 `TaskEventRunner`와 그 핸들러들에 의해 메시지 처리 라이프사이클의 여러 지점에서 호출됩니다.
-   `wait_for_node_completion`: 특정 노드가 완료될 때까지 비동기적으로 기다릴 수 있게 해주는 중요한 메서드로, 복잡한 워크플로우에서 동기화가 필요할 때 사용됩니다.

---

### `EventRuntimeStateManager`

`RuntimeStateManager`를 상속받아 이벤트 시스템의 `Message` 객체와 직접적으로 연동되도록 특화된 클래스입니다.

-   `start_message_node`, `end_message_node`와 같은 편의 메서드를 제공합니다.
-   `TaskEventRunner`는 이 메서드들을 사용하여 메시지가 시스템을 통해 흐를 때 자동으로 상태 그래프를 생성하고 업데이트합니다.

---

### 그룹핑 (`NodeGroup`, `SubGroup`)

상태 관리자는 노드들을 논리적인 그룹으로 묶는 기능을 지원합니다. 이는 여러 개의 하위 태스크를 병렬로 실행하고 그 결과를 취합하는 등 복잡한 워크플로우를 관리하는 데 필수적입니다.

요약하자면, `state_manager.py`는 `TaskEventRunner`의 "기억" 또는 "의식"과 같은 역할을 합니다. 이벤트 실행기는 한 번에 하나의 메시지만 처리하지만, 상태 관리자는 무슨 일이 일어났는지, 누가 누구를 호출했는지, 결과는 어땠는지에 대한 완전한 그래프를 구축하고 유지합니다. 이는 디버깅, 관찰 가능성(observability), 그리고 복잡한 워크플로우 조정에 매우 중요합니다.
