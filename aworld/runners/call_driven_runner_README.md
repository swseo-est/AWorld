# 호출 기반 실행기 모듈 (`call_driven_runner.py`)

이 스크립트는 `EventRunner`의 메시지 기반 방식과는 달리, 보다 직접적이고 명령형(imperative) 스타일로 에이전트 워크플로우를 실행하는 실행기들을 정의합니다. 이 실행기들은 에이전트와 도구를 직접 호출하여 작업을 순차적으로 또는 동적으로 진행시킵니다.

## 주요 구성 요소

### `WorkflowRunner`

`TaskRunner`의 구체적인 구현체로, `WORKFLOW` 빌드 유형을 가진 `Swarm`을 실행하도록 설계되었습니다.

-   **핵심 로직**: `_do_run`과 `_common_process` 메서드에 핵심 로직이 포함되어 있습니다. 이중 루프 구조를 가집니다.
    -   **외부 루프**: 스웜의 `ordered_agents`(순서가 정해진 에이전트 리스트)를 순서대로 순회합니다.
    -   **내부 루프**: 현재 에이전트가 더 이상 도구를 호출하거나 다른 에이전트에게 작업을 위임하지 않을 때(즉, 스스로 "완료"될 때)까지 해당 에이전트를 계속 실행합니다.
-   **실행 방식**: 이벤트 버스 없이 에이전트의 `run` 메서드를 직접 호출하고, 그 결과(정책)에 따라 도구의 `step` 메서드를 직접 호출합니다. 통신은 직접적이고 순차적으로 이루어집니다.
-   **용도**: 미리 정의된 결정론적 순서를 따르는 에이전트 작업(방향성 비순환 그래프, DAG)을 실행하는 데 적합합니다.

---

### `LoopWorkflowRunner`

`WorkflowRunner`를 상속하는 간단한 하위 클래스입니다. `_common_process` 호출을 `for` 루프에 감싸, 동일한 워크플로우를 여러 번 반복하는 태스크를 위해 설계된 것으로 보입니다.

---

### `HandoffRunner`

`TaskRunner`의 또 다른 구체적인 구현체로, `HANDOFF` 또는 `TEAM` 빌드 유형의 `Swarm`을 위해 설계되었습니다.

-   **핵심 로직**: `WorkflowRunner`보다 더 복잡하고 동적인 로직을 가집니다.
    -   "소통 에이전트(communicate agent)"에서 시작하여 루프에 진입합니다.
    -   각 단계에서 현재 에이전트를 실행하고, 그 정책(결과)을 분석합니다.
    -   정책에 따라 다음에 실행할 에이전트를 결정하거나(`_social_agent`), 호출할 도구를 결정합니다(`_social_tool_call`).
-   **실행 방식**: 제어 흐름이 런타임에 에이전트의 결정에 따라 동적으로 결정됩니다. 이를 통해 순환 그래프를 포함한 더 유연하고 협력적인 행동이 가능합니다.
-   **무한 루프 방지**: 무한 순환을 방지하기 위한 루프 탐지 기능이 포함되어 있습니다.

요약하자면, 이 파일은 `EventRunner`의 분리된(decoupled) 메시지 전달 방식과는 대조적으로, 보다 "명령형" 또는 "호출 스택" 기반의 다중 에이전트 상호작용을 위한 실행 로직을 제공합니다. `WorkflowRunner`는 예측 가능한 순차적 워크플로우에, `HandoffRunner`는 에이전트가 다음에 누구에게 "공을 넘길지" 동적으로 결정하는 협업 시나리오에 사용됩니다.
