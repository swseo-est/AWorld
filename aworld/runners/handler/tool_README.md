# 도구 핸들러 모듈 (`tool.py`)

이 스크립트는 `TaskEventRunner` 내에서 에이전트의 도구 호출 요청을 처리하고, 이를 적절한 도구에게 전달하는 "라우터(Router)" 역할을 하는 `DefaultToolHandler`를 정의합니다.

## 주요 구성 요소

### `ToolHandler` (기본 클래스)

도구 관련 핸들러들을 위한 기본 클래스로, `DefaultHandler`를 상속합니다. 실행기(`runner`)의 `tools`와 `tools_conf`에 대한 참조를 초기화합니다.

---

### `DefaultToolHandler`

`Constants.TOOL` 카테고리의 메시지를 처리하도록 등록된 핵심 구현체입니다. 에이전트가 하나 이상의 도구 사용을 결정했을 때, 이 핸들러가 해당 요청을 받아 처리합니다.

#### `_do_handle` 로직

1.  **입력**: 핸들러는 페이로드(payload)로 `List[ActionModel]` (에이전트가 요청한 도구 호출 액션 목록)을 포함하는 메시지를 받습니다.

2.  **동적 도구 로딩**: 액션 목록을 순회하며, 만약 요청된 도구가 현재 실행기에 초기화되어 있지 않다면(`self.tools`에 없다면), `ToolFactory`를 사용하여 즉시 해당 도구의 인스턴스를 생성합니다.
    -   이는 에이전트가 실행 중에 필요한 도구를 동적으로 요청하고 사용할 수 있게 하는 매우 강력한 기능입니다.
    -   새로운 도구가 생성되면, `TaskHandler`에게 `SUBSCRIBE_TOOL` 메시지를 보내 이벤트 버스에 새 도구의 핸들러를 등록하도록 알립니다.

3.  **그룹화 및 디스패치**:
    -   에이전트가 한 번에 같은 도구의 여러 액션을 호출할 수 있으므로, 핸들러는 수신된 액션들을 `tool_name` 기준으로 그룹화합니다.
    -   각 도구 그룹에 대해, 새로운 `Message`를 생성합니다. 이 메시지의 `category`는 여전히 `Constants.TOOL`이지만, `receiver`가 특정 `tool_name`으로 지정됩니다.
    -   이렇게 더 구체화된 메시지를 `yield`하여 이벤트 버스로 다시 보냅니다.

#### 실행 흐름 요약

1.  에이전트가 도구 사용을 결정하고, `TOOL` 카테고리의 메시지를 발행합니다.
2.  `DefaultToolHandler`가 이 메시지를 수신합니다.
3.  필요한 모든 도구가 로드되었는지 확인하고, 없으면 동적으로 로드합니다.
4.  액션들을 도구별로 묶습니다.
5.  각 도구 그룹에 대해, 수신자(`receiver`)가 명시된 더 구체적인 `TOOL` 메시지를 만들어 발행합니다.
6.  `EventManager`는 이 구체적인 메시지를 받아, 해당 도구 이름으로 등록된 핸들러(즉, 도구 자체의 `step` 메서드)를 호출하여 최종적으로 액션을 실행합니다.

결론적으로, `DefaultToolHandler`는 에이전트의 일반적인 도구 호출 요청을 받아, 이를 각 도구가 처리할 수 있는 개별적인 작업 단위로 분배하고 전달하는 중요한 라우팅 허브 역할을 수행합니다.
