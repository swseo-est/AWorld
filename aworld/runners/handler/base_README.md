# 핸들러 기본 모듈 (`base.py`)

이 스크립트는 `TaskEventRunner`의 이벤트 처리 시스템을 위한 기본 "핸들러(Handler)" 아키텍처를 정의합니다. 핸들러는 이벤트 버스를 통해 흐르는 메시지를 가로채서 특정 로직(로깅, 상태 변경, 에러 처리 등)을 수행하는 미들웨어 또는 플러그인과 같은 역할을 합니다.

## 주요 구성 요소

### `Handler` (제네릭 추상 기본 클래스)

시스템의 모든 핸들러를 위한 가장 기본적인 계약을 정의합니다.

-   **`handle` 추상 메서드**: 입력 데이터를 받아 처리하고, 여러 개의 출력 데이터를 `yield`할 수 있는 비동기 제너레이터(`AsyncGenerator`)입니다. 모든 구체적인 핸들러는 이 메서드를 구현해야 합니다.

---

### `DefaultHandler`

`TaskEventRunner`에서 사용되는 모든 구체적인 핸들러들이 상속받는 실질적인 기본 클래스입니다.

-   **메시지 처리**: `Message` 객체를 처리하도록 특화되어 있습니다.

-   **필터링 메커니즘**:
    -   `is_valid_message` 메서드를 통해 자신에게 들어온 메시지를 처리할지 여부를 결정합니다.
    -   하위 클래스에서 `REGISTERED_NAME` 속성(예: `Constants.AGENT`, `Constants.TOOL`)을 정의하면, 핸들러는 해당 `category`를 가진 메시지만을 처리합니다. 이를 통해 각 핸들러가 특정 유형의 이벤트에만 반응하도록 할 수 있습니다.

-   **처리 라이프사이클**:
    1.  `is_valid_message`로 메시지가 유효한지 검사합니다.
    2.  태스크 타임아웃을 확인합니다.
    3.  핵심 로직을 구현하는 `_do_handle` 메서드를 호출합니다.
    4.  `_do_handle`에서 반환된 각 이벤트에 대해 `post_handle`을 호출하여 최종 변환을 수행합니다.

-   **훅(Hook) 시스템**:
    -   `run_hooks` 메서드를 통해 핸들러 자체에도 훅을 연결할 수 있습니다. 이는 매우 세밀한 수준의 커스터마이징을 가능하게 합니다.

-   **기본 동작**: `_do_handle` 메서드의 기본 구현은 받은 메시지를 그대로 다시 `yield`하는 것입니다. 따라서 하위 클래스가 이 메서드를 오버라이드하지 않으면, 해당 핸들러는 메시지를 통과시키는 역할만 합니다.

요약하자면, 이 파일은 `TaskEventRunner`를 위한 강력한 미들웨어 아키텍처의 청사진을 제공합니다. `EventRunner`의 메인 루프는 단순히 메시지를 받아 핸들러를 실행하는 역할만 하고, 실제 프레임워크 레벨의 모든 부가 기능과 로직은 각각의 `DefaultHandler` 하위 클래스에 캡슐화됩니다. 각 핸들러는 이벤트 버스를 흐르는 메시지를 검사하고 변환하는 독립적인 로직 단위입니다.
